# 决策记录 0001：定位调整为面向「画师 / 建模师」的专业工具

- **日期**：2026-10-15
- **状态**：已采纳（用户确认）
- **决策人**：刘义芳
- **取代**：v0.3 文档中「一张立绘 → 全自动生成商业级 Live2D 模型」的定位
- **相关**：`_spec_extract.md`（原始 PRD v0.3）、`docs/decisions/0002`（参考模型结构分析）

---

## 一、决策内容

将产品定位从**面向个人 VUP 的自助成品生成器**，调整为**面向「想省工时的画师 / 建模师」的专业预处理工具**。

具体地：

| 项 | 调整前 | 调整后 |
|---|---|---|
| 目标用户 | 不会 Live2D 的个人创作者 / 虚拟主播 | **已经会绑定、只是不想手工拆图的画师 / 建模师** |
| 核心交付物 | 成品模型（`.moc3` 文件族） | **图层命名规范、画布对齐、遮挡补全完整、带来源追溯的分层 PSD** |
| `.moc3` 生成 | 必经主线 | **降级为可选增强件** |
| 成功标准 | 能加载、能预览、能导出 | **省下的工时 + 客户修正量 + 无格式返工** |
| 竞品 | B站工坊手工皮套 | **Photoshop 手动选区（几乎没有对标产品）** |
| 商业化路径 | 自助 SaaS，走量 | **工具 + 按张服务，走专业圈口碑** |

---

## 二、为什么做这个调整

### 2.1 技术侧：成品价值集中在无法自动复现的那一层

对 VTube Studio 里一套真实在售的商业成品皮套（`困困抱猫枕`）做结构分析后确认，其构成可拆为四层：

| 层 | 内容 | 自动生成可行性 |
|---|---|---|
| ① 文件族外壳 | `model3.json` / `exp3.json` / `cdi3.json` / `vtube.json` 的 schema 与字段 | 接近 100%，纯数据 |
| ② 参数与 Part 命名 | 45 个标准 Cubism 参数 + 自定义参数、45 个 Part | 可自动生成，但须跟随绑定结果 |
| ③ 物理链 | 5 条链、17 输入 / 29 输出 | 可模板化，但抖动质感须人工调 |
| ④ `.moc3` 内的实体 | 网格细分、Part → 变形器（Rotation / Warp）层级、角度关键帧、纹理图集像素 | **无法自动复现，占主要工作量** |

关键事实：**该成品的价值几乎全部集中在第 ④ 层，而这恰是自动生成最弱的环节。** 同时第 ① 层极便宜（单个表情文件仅 209 字节，本质是「把某参数设为 1.0」的 JSON），导致容易出现「文件族齐全、能加载、但动起来难看」的伪成功。

### 2.2 客户侧：专业客户自己就能完成第 ④ 层

- 专业客户最终使用的软件是 **Cubism Editor 与 Photoshop，两者都直接支持导入分层 PSD**。
- 他们自己绑得比自动工具好，因此**不需要我们交付成品**。
- 他们真正嫌烦的是：拆图、遮挡补全、画布对齐、图层命名——**这正是可自动化的部分**。

### 2.3 风险侧：该调整一次性拆除两个最大风险

- **不再需要逆向 `.moc3`**（闭源二进制格式，无公开写入器）
- **主流程不再强依赖 GPL-3.0 的 psd2live**（改为可选增强件，法律审查可后置）

### 2.4 商业侧：单位经济性更适合 1 人冷启动

| 变量 | 面向个人（自助 SaaS） | 面向专业（工具 + 服务） |
|---|---|---|
| 客单价 | ¥29–99 | **¥150–400 / 张** |
| 达 ¥36,000/月 所需客户数 | 400–1,200 单 | **约 90–240 张** |
| 获客成本 | 高（须买量或分销，当前无渠道） | **低（专业社群口碑 + 复购）** |
| 单客支持成本 | 极高（不会排查、退款、反复问） | **低（自己会修，且会给出有效反馈）** |
| 竞争 | 与手工皮套正面撞质感 | 基本无对标产品 |
| 月毛利估计 | ¥10,000–15,000（扣分销/获客/退款） | **¥5,000–20,000，毛利 80%+** |

决定性差异在**支持成本**：一个不会用的个人用户消耗的客服时间是专业建模师的 5–10 倍；而个人路线的成败取决于渠道（流量/分销），当前不具备。

### 2.5 保留的备选路径

个人自助版不作为首批目标，但保留为**第 3 步可选路径**，且必须走分销渠道，不自建流量。
前置条件：专业路线已建立口碑、有稳定客源与已验证的交付能力。

## 三、该决策带来的具体改变

### 3.1 优先级重排（改动 v0.3 文档第 10 章）

| 原顺序 | 新顺序 |
|---|---|
| 阶段 0：尽调绑定工具 | **阶段 0：尽调 Cubism Editor 的分层 PSD 导入规范 + 分层 / 补全模型选型** |
| 阶段 1：PoC＝自动绑定链路 | **阶段 1：PoC＝「立绘 → 规范分层 PSD」闭环** |
| 阶段 2/3：MVP 后端 / 前端 | 不变 |
| 绑定 / `.moc3` | **降级为阶段 2 的可选增强，且须先做许可证审查** |

预期效果：阶段 0/1 的成本与时间显著下降（不必啃 `.moc3` 二进制、不必先解决 GPL），而交付价值更明确。

### 3.2 产品铁律（由新定位直接推导）

1. **图层零丢失。** 未识别图层一律保留为 `unknown_*`。丢掉一个图层等于废掉客户整套素材，比画错严重得多。
2. **来源可追溯。** 每个补全图层、每个 `unknown_*` 必须标注来源与生成参数。对专业客户，「可追溯」比「好看」值钱——他会自己改，但不能接受「不知道哪块是 AI 猜的」。
3. **如实标注，不伪装质量。** 低置信度区域标记为 `needs_review` 是**功能与卖点**，不是妥协。此客户群本就预期要手工修正。
4. **无格式返工。** 输出的 PSD 必须能被目标编辑器直接导入使用，不需要格式转换。
5. **不伪造成功。** 遵循 v0.3 文档 12.3 全部禁止事项。

### 3.3 保留不变的部分

- 数据契约思路（`job_id`、中间文件命名含任务 ID 与阶段、避免互相覆盖）
- 任务状态机（v0.3 文档 3.2 的 11 个状态）
- 错误码体系（v0.3 文档 7.2 的 11 个错误码）
- 质量门禁与可复现性要求（7.1、7.3）
- 安全与版权条款（第 8 章）
- AI 编程代理工作规范（第 12 章）

## 四、已识别的代价与风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 市场更窄 | 客户数远少于个人市场 | 客单价高、复购强、获客成本低；以「省工时」而非「成品质量」定价 |
| 工具化而非产品化 | 不易做成订阅制 SaaS | 采用「工具 + 按张服务 / 包月分包」混合模式；后期可做白标授权给建模师转售 |
| 单价依赖客户工时成本 | 若客户时薪低，付费意愿下降 | 定价对标其手工拆图耗时（按 ¥100/h 估算其可承受区间） |
| PoC 出口标准改变 | 原「可运行模型」标准不再适用 | 见 `0003-验收标准` |

## 五、待确认事项（未决，不阻塞文档）

1. **交付物形态**：确认核心产物＝分层 PSD + 补全层 + 来源追溯报告；`.moc3` 为可选增强件。
2. **客户主力编辑器**：Cubism Editor 占主导，还是存在 Spine / AE / 自研等分流？若以 Cubism Editor 为主，PSD 图层规范可收得更紧。
3. **命名规范归属**：目标客户是否已有自己的图层命名习惯？建议标准标签实现为**可配置映射**（客户命名 ↔ 标准标签 ↔ 未来绑定工具要求），而非硬编码。
4. **网络阻塞**：当前沙箱内 PowerShell 无法访问任何外网（GitHub / PyPI / 国内镜像均不通），阶段 0 实测依赖无法获取。须由用户放开外网或手工下载。
