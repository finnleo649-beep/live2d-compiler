### 与官方参考输出对比（`moc3-cmo3-output/`）

| 文件 | 生成 | 官方参考 | 判断 |
|---|---|---|---|
| `model3.json` | 701 B | 701 B | **完全一致** |
| `blink.motion3.json` | 1,155 B | 1,155 B | **完全一致** |
| `nod.motion3.json` | 1,751 B | 1,751 B | **完全一致** |
| `shake.motion3.json` | 1,573 B | 1,571 B | 接近 |
| `physics3.json` | 8,581 B | 8,555 B | 接近 |
| `cdi3.json` | 4,380 B | 4,029 B | 接近 |
| `texture_00.png` | 2,307,809 B | 2,310,265 B | 接近 |
| `idle.motion3.json` | 15,999 B | 2,282 B | **差异大**（idle 循环更长） |
| `moc3` | 331,840 B | 106,368 B | **差异大（约 3 倍）** |
| `cmo3` | 4,924,850 B | 4,148,007 B | 差异较大 |
| `can3` | 17,477 B | 无 | 额外产物（新版本） |

**moc3 差异原因**：CLI 默认网格参数（`--mesh-spacing 64`、`--atlas 4096`）与官方参考生成时的设置不同；官方参考的具体设置未记录。**这是参数差异，不是失败**，可用 `--mesh-spacing` 等参数调整。

### 关键发现

1. **生成的 `model3.json` 正确填充了 `EyeBlink` / `LipSync` 组**：
   ```json
   "Groups": [
     {"Target":"Parameter","Name":"EyeBlink","Ids":["ParamEyeLOpen","ParamEyeROpen"]},
     {"Target":"Parameter","Name":"LipSync","Ids":["ParamMouthOpenY"]}
   ]
   ```
   对比「困困抱猫枕」参考模型这两组为空，**psd2live 产出的模型对 VTS 面捕更友好**。
2. 生成过程输出警告：`检测到同类图层：handwear, ears, eyewhite, irides, eyelash, eyebrow，可能通过比对图层 ID 区分`——印证 v0.3 文档 4.4「绑定工具依赖图层命名与素材拆分规范」，**必须通过真实 PSD 验证输入要求**。

## 四、许可证与能力边界

| 项 | 结论 |
|---|---|
| psd2live 主许可证 | **GPL-3.0**（LICENSE 第 1 行确认） |
| 模块许可差异 | 中立 IR `:format-model`、导出框架 `:format-compile`、光栅导出 `:targets:raster`、运行时 `:targets:runtime`、`:format-eval` 为 **MIT**；`:targets:cubism`（moc3/cmo3）与 `:targets:psd` 使用引擎 |
| 官方 Cubism SDK | **不是构建前提**；源码构建默认用内置渲染 |
| 无界面 MCP | **支持**（`--args="mcp ..."`，供智能体驱动） |
| 补全能力实际表现 | psd2live 自己的 `docs/zh/STATUS.md` 实测表记录：**「头发拆分与遮挡补全 = 已验证 / 评价：不可用」**；「简单图层切分 = 未测」 |

## 六、结论与下一步

**阶段 0 退出条件（v0.3 文档第 10 章）已达成**：
> 「至少有一条候选技术路线能产生可在目标运行时加载的模型」

**但仍有关键缺口**：
1. **moc3 能否在 VTube Studio 真正加载**——需要实际加载测试（下一步）

3. **补全能力**——psd2live 自评「不可用」，需另找补全方案
4. **GPL 合规**——商业服务架构必须先定隔离方案

**建议下一步（阶段 1 PoC）**：
- 用 VTube Studio 实际加载生成的 `tml.model3.json`，验证面捕（眨眼/口型/头部角度）
- 建立固定的 CLI 批处理封装（把 gradlew 调用、参数、错误码标准化）
