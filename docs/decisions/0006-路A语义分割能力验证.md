## 二、模型能力验证

### 输入
从 psd2live 示例 `tml.psd` 合并图裁剪出**单个角色的上半身**（740×920）。注意：`tml.psd` 是双人调试图，直接整图送模型会被误判为 `hat 50%`，**必须先裁剪出单人**。

### 输出（19 类中的实际命中）

| 类别 | 像素 | 占比 | 视觉核对 |

| background | 271,448 | 39.9% | ✅ |
| **hair（头发）** | 343,794 | **50.5%** | ✅ 精确覆盖全部头发 |
| **skin（皮肤）** | 50,920 | 7.5% | ✅ 脸 + 脖子 |

**结论**：分割 mask 与原图视觉完全对应（头发=绿、皮肤=蓝、眼睛=深色块），**这是可用的语义分层能力**。

## 三、当前边界（必须如实记录）

1. **只覆盖头部/上半身**：face-parsing 在 CelebAMask-HQ（人脸数据集）上训练，对人体、四肢、手部分割能力有限；全身立绘需补充方案。
2. **对输入敏感**：整图含多人物或人物占比过小时会严重误判（实测 `hat` 误判 50%），**必须先检测并裁剪单人**。
3. **非动漫专用**：模型在真人脸数据集上训练，对动漫风格可用但不完美（眉毛识别较弱，`l_brow` 仅 1 px）。
4. **CPU 推理**：单张 2048 图像约数十秒；上 GPU（4060）会显著加速。

## 四、下一步

1. **封装成分割模块**：把 face-parsing 包装成 `pipeline/stages/segment_semantic.py`，替换路 B 的 `segment_layers`（接口不变）。
2. **解决"单人物裁剪"**：加前景检测 + 最大连通区域，自动裁出人物再送模型。
3. **补全身方案**：
   - 头部：face-parsing（现状）
   - 身体/衣服：人体解析模型（如 SCHP / ATR）或颜色聚类辅助
   - 头发前后分层：按纵向位置或深度启发式切分
4. **标签映射**：19 类 → v0.3 文档 4.2 的标准标签（`hair` → `hair_front`/`hair_back`，`l_eye` → `eye_L_*`，`skin` → `face_base` …）。
5. **GPU 加速**：装 CUDA 版 torch（约 2.5GB），用 4060 跑。

## 五、混合方案实测（2026-10-17 补充）

针对「face-parsing 只擅长头部」的限制，实现了**混合分层**：
- **头部区域**（人物 bbox 顶部 50%）→ AI 语义分割 → 标准标签图层
- **身体/腿部区域** → 颜色聚类 → `body_color_*` 图层
- 前景兜底 → `unknown_foreground`

### 测试素材
用 `psd-tools` 把 `tml.psd` 的 22 个图层合成为**干净原色立绘**（`tml_clean.png`，透明背景，2048×2048）。

### 结果

| 指标 | 结果 |
|---|---|
| 图层数 | **16** |
| coverage | **1.0**（零丢失） |
| 合成预览 | 与原图视觉一致 |

图层构成：
- **语义层（face_parsing）**：`hair_front` 86k px、`face_base` 56k px、`eye_L_base` / `eye_R_base`、`clothes_base` 92k px、`accessory_hat` 261k px
- **身体颜色层（color_cluster）**：`body_color_00` ~ `body_color_07`（8 层）
- **兜底**：`unknown_foreground` 40k px

### 如实记录的模型局限

| 问题 | 表现 | 原因 |
|---|---|---|
| `accessory_hat` 误判 | 261k px（抢占头发），置信度仅 **0.58** | 角色头上有「角」，模型把它当帽子 |
| `accessory_glasses` 误判 | 1.5k px | 眼部区域被误判 |
| 眉毛/嘴部缺失 | 未产出 `brow_*` / `mouth_cavity` | 动漫细线条 + 训练数据差异 |
| 身体无语义 | 只有 `body_color_*` | 未接入人体解析模型 |

**结论**：工程链路（裁剪→分割→映射→零丢失→manifest）已完整可用；**语义精度受模型限制**，动漫风格需要专门的动漫分割模型才能达到画师可用标准。

### 下一步建议
1. 换**动漫专用**分割模型（而非真人脸模型）
2. 或对 `accessory_hat` 加后处理规则（大面积低置信度的 hat 重分配为 hair）
3. 身体接入人体解析模型（SCHP / ATR）
4. 上 GPU 提速（当前 CPU 单张约数十秒）

## 六、后处理规则实测（2026-10-17 补充）

针对模型明显误判，实现两条后处理规则（`pipeline/stages/segment_semantic.py::_postprocess_labels`），
修正记录写入 `layer_manifest.json` 的 `postprocess_notes` 字段（可追溯）。

### 规则 1：`accessory_hat` 误判修正
- **触发**：hat 面积 > 头部前景 25%，且平均置信度 < 0.7
- **处理**：**头部区域上部 50%** 的 hat → `hair_front`；其余 → `unknown_foreground`
- **理由**：角色头上的「角 / 发饰」常被误判为帽子；且 hat 区域往往连带覆盖上半身衣服，
  整块并入头发会污染 hair 层。

### 规则 2：小配件合并
- glasses / earring / necklace 面积 < 头部前景 1% → 合并到相邻主层（face_base / hair_front / clothes_base），
  避免产生无意义碎层。

### 实测效果对比（`tml_clean.png`）

| 版本 | hair_front | unknown_foreground | 评价 |
|---|---|---|---|
| 无后处理 | 86k px | 40k px | `hat` 261k px 抢占头发 |
| 粗暴合并 hat→hair | 347k px | 40k px | 围裙被混入 hair |
| 头部上部 70% 切分 | 283k px | 104k px | 仍有围裙残留 |
| face_base bbox 定位 | 347k px | 40k px | 几乎全吞（脸 bbox 太宽） |
| **上部 50% 切分（最终采用）** | **184k px** | **203k px** | **头发干净，围裙归 unknown** |

### 已知未解决案例
「**白发 + 白围裙**」角色（tml）中，头发与围裙**颜色相同、空间重叠**，任何矩形 / 颜色启发式都无法完美切分。
当前策略是**「宁可少分也不污染」**——未被确认的部分归 `unknown_foreground`，保留原始像素交画师判断，
符合「图层零丢失 + 来源可追溯」铁律。
